# Тестирование сервисного слоя

## Требования и команды запуска

Нужен JDK 25. Maven устанавливается скриптом Maven Wrapper при первом запуске.
Команды выполняются из корня проекта в PowerShell.

Только модульные тесты (без PostgreSQL, Docker и переменной `DB_PASSWORD`):

```powershell
.\mvnw.cmd test
```

Все модульные и интеграционные тесты:

```powershell
.\mvnw.cmd -Ppostgres-tests verify
```

Для второго варианта требуется установленный и запущенный Docker с поддержкой
Linux-контейнеров. Testcontainers сам загружает образ `postgres:17-alpine`, создаёт
контейнер с БД `tour_agency_test`, выбирает свободный порт и удаляет контейнер после
тестирования. Первый запуск требует доступа к Maven Central и реестру образов.
При отсутствии Docker интеграционный набор завершается ошибкой, а не скрытым пропуском.

Запуск одного модульного класса:

```powershell
.\mvnw.cmd -Dtest=BookingServiceTest test
```

На Linux/macOS используются те же параметры с `./mvnw` вместо `.\mvnw.cmd`.

### Docker в Ubuntu WSL

Docker в WSL доступен процессам внутри Ubuntu. Запущенный из Windows Maven не
обязательно видит этот Docker: наличие работающего демона в WSL само по себе
не предоставляет Windows-процессу доступ к его Unix-сокету.

Если в Ubuntu установлен JDK 25, можно перейти в папку проекта и выполнить:

```bash
bash ./mvnw -Ppostgres-tests verify
```

Если Java в Ubuntu не установлена, используйте подготовленный скрипт:

```bash
cd '/mnt/d/Учеба/Университет/3 курс/Курсовая работа/tour-agency'
bash scripts/test-wsl.sh
```

Он запускает Maven с JDK 25 в Linux-контейнере, передаёт Docker-сокет WSL и
использует сеть хоста для соединения с тестовой PostgreSQL. Устанавливать JDK
в Ubuntu или открывать Docker API по TCP не требуется. Зависимости Maven
кешируются в отдельном Docker volume `tour-agency-test-maven-cache`.
Отчёты сохраняются в той же папке `target` проекта и доступны из Windows.

Скрипту можно передавать другие параметры Maven, например только модульные тесты:

```bash
bash scripts/test-wsl.sh test
```

## Изоляция базы данных

Интеграционные тесты используют `@DynamicPropertySource`: URL, имя пользователя
и пароль берутся исключительно у временного контейнера. Они переопределяют
настройки подключения из `application.properties`. Рабочая БД не используется.

Профиль `postgres-test` включает `create-drop`: схема создаётся из JPA-моделей.
Перед каждым интеграционным тестом очищаются таблицы **внутри контейнера** и создаются
исходные записи. Пользовательские данные и содержимое локальной PostgreSQL не меняются.
Не следует переносить настройки `create-drop` в основной профиль приложения.

Это проверка схемы, построенной по моделям. Соответствие вручную созданной рабочей
схеме, её собственных CHECK-ограничений, индексов и миграций отдельно не проверяется:
SQL-миграций в репозитории пока нет.

## Модульные тесты

Файлы находятся в `src/test/java/ru/naboyshchikovfp/tour_agency/services`.
JUnit запускает тесты, AssertJ проверяет результаты, Mockito заменяет репозитории.

| Класс | Проверяемые сценарии |
| --- | --- |
| `UserServiceTest` | Нормализация email и имён, передача пароля кодировщику, несовпадение паролей, занятый email, изменение профиля без смены учётных данных, блокировка |
| `CustomUserDetailsServiceTest` | Поиск по нормализованному email, передача сохранённого хеша, роли и признака блокировки, неизвестный пользователь |
| `HotelServiceTest` | Создание и изменение, дубликаты названия, исключение текущей записи при проверке уникальности, запрет удаления используемого отеля |
| `TourServiceTest` | Некорректные диапазоны фильтра, отсутствующий отель, запрет смены отеля и ночей у забронированного тура, изменение цены, ограничения удаления |
| `BookingServiceTest` | Расчёт суммы, текущий владелец, запрет операций с чужими записями, разрешённые и запрещённые статусы, граничные даты отмены, подтверждения, оплаты и завершения |
| `FavoriteServiceTest` | Добавление от имени текущего пользователя, повторное добавление, отсутствующий тур, удаление и повторное удаление, преобразование списка |
| `ReviewServiceTest` | Отзыв по своей завершённой поездке, запрет отзыва при остальных статусах и повторного отзыва, чужое бронирование, отсутствие тура или отзывов |

В модульных тестах сервис создаётся без Spring-прокси. Поэтому `@PreAuthorize`,
`@Valid` и фактическое сохранение изменений JPA проверяются интеграционным набором.
Отдельные тесты на простые геттеры и сеттеры не добавлены.

Моки создаются для интерфейсов репозиториев и `PasswordEncoder`. Используется
`mock-maker-proxy`, которому не требуется подключать Java-агент в контейнере.
Этот режим поддерживает только интерфейсы; для будущих моков классов потребуется
другой режим. Описание: [Mockito MockMakers](https://javadoc.io/static/org.mockito/mockito-core/5.23.0/org.mockito/org/mockito/MockMakers.html).

## Интеграционные тесты

`integration/ServicesPostgresIT.java` поднимает полный Spring-контекст с настоящими
сервисами, репозиториями и PostgreSQL. Класс запускается Maven Failsafe только в
профиле `postgres-tests`, поскольку имя заканчивается на `IT`, а не `Test`.

Проверяются:

- регистрация с настоящим BCrypt и сохранение даты создания;
- сохранение профиля и блокировки без явного `save()`;
- пагинация пользователей, создание, изменение и удаление отелей и туров;
- сочетание всех фильтров каталога, регистр, границы диапазонов, сортировка и страницы;
- создание бронирования и сохранение переходов `NEW → CONFIRMED → PAID`;
- сохранение `CANCELLED` и `COMPLETED`, запрет чужих операций и недопустимых переходов;
- неизменность суммы существующего бронирования после изменения цены тура;
- добавление, изоляция и удаление избранного;
- создание одного отзыва по завершённой поездке и публичное чтение с именем автора;
- ограничения PostgreSQL: уникальность email, пары пользователь–тур и отзыва по бронированию, внешний ключ от тура к отелю;
- проверки ролей и отсутствие авторизации через настоящие Spring-прокси;
- валидация DTO и запрет `null` до сохранения в БД.

Тесты не обёрнуты в общую тестовую транзакцию: сервис завершает собственную
транзакцию, затем запись загружается повторно. Так обнаруживаются ошибки, при которых
объект изменился в памяти, но изменение не сохранилось. Open Session in View отключён,
поэтому преобразование ленивых связей в DTO также проверяется.

Сведения о текущем пользователе задаются через `SecurityContextHolder` и очищаются
после теста. Это проверяет авторизацию методов, но не отправку HTML-формы входа:
HTTP-контроллеры и страницы пока не реализованы.

## Результаты и ограничения

Проверка 4 ноября 2026 года в Ubuntu WSL через `bash scripts/test-wsl.sh`:
73 модульных и 26 интеграционных тестов прошли, ошибок и пропусков нет.
Результат Maven — `BUILD SUCCESS`. Интеграционные тесты выполнялись на PostgreSQL
17.11 с настоящим подключением к временной базе контейнера.

Первоначальный запуск Maven из Windows не обнаружил Docker, работающий в Ubuntu.
Запуск внутри WSL через Maven-контейнер решил проблему подключения. Для Mockito
добавлен режим `mock-maker-proxy`, позволяющий выполнять моки интерфейсов без
успешного подключения Java-агента к JVM контейнера.

XML- и текстовые отчёты модульных тестов: `target/surefire-reports`.
Интеграционные отчёты: `target/failsafe-reports`.
Их можно использовать как подтверждение запуска в разделе курсовой о тестировании.
Успешная компиляция интеграционных тестов сама по себе не означает, что они прошли:
для проверки PostgreSQL нужен успешный запуск `-Ppostgres-tests verify`.

Текущие наборы не проверяют конкурентные запросы, нагрузку, настоящую платёжную
систему и завершение уже открытых сессий заблокированного пользователя. Имитация
оплаты проверяется только как переход статуса. Даты вычисляются относительно дня
запуска, поэтому тесты не привязаны к конкретному месяцу или году; запуск через
полночь может потребовать повторения, поскольку сервисы пока используют `LocalDate.now()`.

Прежний пустой `contextLoads()` заменён интеграционным набором: загрузка полного
контекста теперь происходит с отдельной PostgreSQL, а обычный `test` не требует
подключения к рабочей БД.

Описание жизненного цикла контейнеров и настройки подключения:
[Testcontainers for Java](https://java.testcontainers.org/),
[Spring Boot: Testcontainers](https://docs.spring.io/spring-boot/reference/testing/testcontainers.html).
